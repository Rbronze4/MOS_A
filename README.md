# MOS開発でAIを使うときのルールとプロンプト

> **はじめてこのシステムを触る方へ**
> 環境構築の手順は **[SETUP.md](SETUP.md)** にまとまっています。
> XAMPPの導入からDBの取り込みまで、上から順に進めれば動くようになっています。

## 各画面のURL（XAMPP起動時）

- 利用客画面：`http://localhost/MOS_A/public/customer`
- スタッフ画面：`http://localhost/MOS_A/public/staff`
- （参照用）レジシステム：`http://localhost/regi/public/`　※htdocs直下に`regi`を配置している想定
- レジ連携API（レジが叩く）：`http://localhost:8080/api/orders`　※セットアップは「レジ連携（regi）のローカルセットアップ」を参照

---

MOSを多人数で開発する場合、AIに自由にコードを書かせると、既存の画面・JavaScript・DB・API仕様を壊してしまう可能性があります。

HTMLの `id`、CSSの `class`、JavaScriptの関数名、PHPのルート、DBカラム名、API仕様がつながっています。
そのため、AIが勝手に名前を変更すると、画面は表示されてもボタンが動かない、DBに登録できない、API連携できないといった問題が起きます。

そのため、AIに依頼するときは、毎回以下のルールを守ってください。

---

## AIに依頼するときの基本ルール

### 1. 1回の依頼で1機能だけ頼む

悪い例：

```text
注文一覧を直して、スタッフ注文も追加して、ログアウトの404も直して、客側のタブ矢印も追加してください。
```

良い例：

```text
今回はログアウトボタン押下時の404エラーだけを修正してください。
```

1回の依頼で複数の機能をまとめて頼むと、AIが関係ない部分まで変更してしまう可能性があります。

---

### 2. 変更してよいファイルを明記する

AIが関係ないファイルまで勝手に変更しないように、必ず変更してよいファイルを書きます。
また、変更すべきファイルをAIに特定させて、ファイルを変更してよいか確認してください。

例：

```text
【変更してよいファイル】
- src/Views/staff/order_list.php
- public/assets/css/staff.css
- public/assets/js/staff-order.js
```

---

### 3. 現在のコードを必ず貼る

AIに想像でコードを書かせると、存在しないファイル名・関数名・DBカラム名を使う可能性があります。

そのため、必ず現在のコードを貼ってから依頼してください。

```text
以下が現在のコードです。
このコードをベースに修正してください。
省略せず完全版で返してください。
```

---

### 4. 既存のID・class・関数名・ルート名を勝手に変えさせない

HTMLの `id` や CSSの `class` は、JavaScriptやCSSとつながっています。

例えば、既存コードで以下のように使っている場合、

```html
<button id="cartButton">カート</button>
```

AIが勝手に以下のように変更すると、

```html
<button id="cart-btn">カート</button>
```

JavaScript側で `cartButton` を探している処理が動かなくなる可能性があります。

そのため、以下の指示を必ず入れてください。

```text
既存のid、class、関数名、ルート名を勝手に変更しないでください。
```

---

### 5. DB構造を勝手に変更させない

DB変更は影響範囲が大きいため、AIに勝手に追加・変更させないでください。

```text
DB構造を勝手に変更しないでください。
DB変更が必要な場合は、先に理由を説明してください。
```

---

### 6. コードは省略なしの完全版で出してもらう

一部だけ出されると、どこに貼ればよいか分かりにくく、ミスが起きやすいです。

```text
コードは省略しないでください。
「既存部分はそのまま」などの省略表現は使わず、コピペで差し替えられる完全版を出してください。
```

---

### 7. コメントは多めに書いてもらう

後から別のメンバーが読んでも処理の流れが分かるように、コメントを多めに書いてもらいます。

ただし、当たり前すぎるコメントではなく、**なぜその処理が必要なのか** が分かるコメントを優先してください。

悪いコメント例：

```php
// if文です
if ($status === 2) {
}
```

良いコメント例：

```php
// 会計済みの注文は二重会計を防ぐため、再度清算処理に進ませない
if ($status === 2) {
}
```

---

### 8. 最後に動作確認手順も出してもらう

コードを出して終わりではなく、何を確認すればよいかもAIに出してもらってください。

例：

```text
【動作確認】
1. 注文一覧画面を開く
2. 「1つ提供」を押す
3. 提供数が1増えることを確認する
4. 「1つ減らす」を押す
5. 提供数が1減ることを確認する
6. 提供数が0未満にならないことを確認する
```

# AIに貼るプロンプトテンプレート

以下をコピーして、必要な部分を書き換えて使ってください。

```text
あなたはMOS開発の補助AIです。
以下の既存仕様と開発ルールを必ず守ってください。

【開発環境】
- PHP
- JavaScript
- HTML/CSS
- MySQL
- XAMPP
- MVC構成

【MOSの前提仕様】
- 居酒屋向けのモバイルオーダーシステムです
- 客側画面、店員側画面、レジ側画面があります
- 注文一覧、提供済み一覧、キャンセル済み一覧があります
- APIは POST /api/orders を使用します
- method は getOrders または updateStatus です
- customerId は7桁です
- storeId は大文字アルファベット2文字です
- 会計済みにする場合は billStatus=2 です
- getOrders は注文取得のみで、状態更新はしません
- updateStatus で注文状態を更新します

【今回の目的】
ここに今回実現したい内容を書いてください。

例：
スタッフ側の注文一覧画面で、「1つ提供」「全て提供」「1つ減らす」の3つのボタンを1行で表示し、それぞれ正しく提供数を変更できるようにしたいです。

【現在の問題】
ここに現在困っていることを書いてください。

例：
現在は操作ボタンが2段になっていて見た目が悪いです。
また、「1つ減らす」を押したときに注文個数まで減ってしまう可能性があります。

【変更してよいファイル】
以下のファイルだけを変更してください。

- ここに変更してよいファイル名を書く
- 例：src/Views/staff/order_list.php
- 例：public/assets/css/staff.css
- 例：public/assets/js/staff-order.js

【変更してはいけないこと】
- 指定したファイル以外は変更しないでください
- 既存のid、class、関数名、ルート名を勝手に変更しないでください
- DB構造を勝手に変更しないでください
- 既存機能を削除しないでください
- 指示していない画面に影響を出さないでください
- API仕様を勝手に変更しないでください
- 既存コメントはできるだけ残してください
- 処理を大きく作り直す場合は、先に理由を説明してください

【コメント方針】
- 初学者でも処理の流れが分かるように、コメントを多めに書いてください
- コメントは日本語で書いてください
- 特に、条件分岐・ループ・DB処理・API通信・画面更新処理にはコメントを付けてください
- 「何をしているか」だけでなく、「なぜその処理が必要なのか」が分かるコメントを優先してください
- MOS独自の仕様に関係する処理には必ずコメントを入れてください
- ただし、1行ごとに当たり前の説明をするコメントは避けてください

悪いコメント例：
「if文です」
「変数に代入します」

良いコメント例：
「会計済みの注文は二重会計を防ぐため、再度清算処理に進ませない」
「提供数が注文数を超えないように、最大値を注文数に制限する」

【現在のコード】
以下に現在のコードを貼ります。
このコードをベースに修正してください。
省略せず、差し替え可能な完全版で返してください。

ここに対象ファイルのコードを貼る。

【期待する動作】
以下の動作になるようにしてください。

1. ここに期待する動作を書く
2. ここに期待する動作を書く
3. ここに期待する動作を書く

例：
1. 「1つ提供」を押すと、提供数が1増える
2. 「全て提供」を押すと、提供数が注文個数と同じになる
3. 「1つ減らす」を押すと、提供数だけが1減る
4. 提供数は0未満にならない
5. 注文個数は変更されない

【出力してほしいもの】
以下の順番で出力してください。

1. 修正するファイル一覧
2. 修正内容の概要
3. 各ファイルの完全版コード
4. 変更したポイントの説明
5. 動作確認手順

【注意】
コードは省略しないでください。
「既存部分はそのまま」などの省略表現は使わず、コピペで差し替えられる完全版を出してください。
```

# DBのインポート方法

MOSを動かす前に、必要に応じてデータベースを作成し、SQLファイルをインポートしてください。

## 手順

1. XAMPPを起動する
2. XAMPPの画面から **Apache** と **MySQL** を起動する
3. MySQLの **Admin** をクリックして、phpMyAdminを開く
4. `mos_a_system` データベースをまだ作成していない場合は、以下の内容で新規作成する

   * データベース名：`mos_a_system`
   * 文字コード：`utf8mb4_unicode_ci`
5. 作成した `mos_a_system` データベースを選択する
6. 画面上部の **インポート** をクリックする
7. インポートするSQLファイルを選択する
8. **インポート実行** をクリックする

## 注意点

* すでに `mos_a_system` データベースが存在する場合は、新規作成は不要です
* インポート先のデータベースを間違えないように、必ず `mos_a_system` を選択してからインポートしてください
* 文字コードは `utf8mb4_unicode_ci` を選択してください
* インポート時にエラーが出た場合は、同じテーブルがすでに存在していないか確認してください

# レジ連携（regi）のローカルセットアップ

MOSとレジ（regi）は、**`POST /api/orders` のHTTP APIだけ**で連携します。両者はDBもコードも共有しません。
（MOS側のAPI仕様や設計の詳細は `docs/regi-api-orders-design.md` を参照）

本番ではMOSとレジは別ホストに置かれ、レジは「MOS専用のアドレス」に対してAPIを叩きます。
ローカルでもこの形に近づけるため、**MOSを専用ポート `:8080` でも配信**し、
レジのデフォルト設定（`base_url = http://localhost:8080`）を変えずに連携できるようにしています。

## ⚠️ 最初に読んでください（cloneしただけでは動きません）

このリポジトリを clone / pull しても、**レジ連携はそのままでは動きません**。
Apacheの設定はリポジトリの外（`xampp/apache/conf/`）にあり、各自の環境ごとに手作業が必要だからです。

| 手に入るもの（リポジトリ内） | 各自でやること（リポジトリ外） |
| --- | --- |
| APIコード（`src/Controllers/ApiOrderController.php` ほか） | Apacheに `Listen 8080` とvhostを追加（本セクションの手順） |
| このセットアップ手順（README） | DBのインポート（「DBのインポート方法」を参照） |
| DBのSQL（`DB/developing/*.sql`） | Apacheの再起動 |

とくに **vhostの `DocumentRoot` は各自のパスに書き換えが必須**です（後述）。
コピペしただけでは動かない点に注意してください。

## アクセス経路の整理

| 用途 | URL | ポート |
| --- | --- | --- |
| 人間が使うMOSの画面 | `http://localhost/MOS_A/public/...` | 80（従来どおり） |
| レジが叩くMOSのAPI | `http://localhost:8080/api/orders` | 8080（サーバー間通信用） |
| レジ本体 | `http://localhost/regi/public/` | 80 |

> ポート80とポート8080は同じMOSを配信しますが、MOSの画面は `/MOS_A/public` を前提に
> 作られているため、**人間はポート80、レジ（API）はポート8080**を使い分けます。

## セットアップ手順（初回のみ）

### 1. Apacheに `:8080` を追加する

`apache/conf/httpd.conf` の `Listen 80` の下に1行追加する。

```apache
Listen 80
Listen 8080
```

### 2. `:8080` の仮想ホストを追加する

まず、**自分の環境でのMOSの `public` フォルダの絶対パス**を確認する。これはXAMPPの置き場所によって人それぞれ違う。

| XAMPPの場所 | `public` の絶対パスの例 |
| --- | --- |
| `C:\xampp`（既定） | `C:/xampp/htdocs/MOS_A/public` |
| デスクトップ等に配置 | `C:/Users/自分の名前/Desktop/xampp/htdocs/MOS_A/public` |

> 分からない場合は、エクスプローラーで `MOS_A/public` フォルダを開き、アドレスバーのパスを確認する。
> Apacheの設定では区切りを **`/`（スラッシュ）** で書く（`\` ではない）。

次に `apache/conf/extra/httpd-vhosts.conf` の末尾に以下を追加する。

> 🔴 **必ず書き換えること**：下の `★ここを自分のパスに★` の**2箇所**を、上で確認した絶対パスに置き換える。
> この2箇所を変えないと、他人のパスのままになり **動きません**（`AH00112` などのエラーになる）。

```apache
<VirtualHost *:8080>
    DocumentRoot "★ここを自分のパスに★/MOS_A/public"

    <Directory "★ここを自分のパスに★/MOS_A/public">
        Options FollowSymLinks
        AllowOverride None
        Require all granted

        DirectoryIndex index.php

        # public/.htaccess は RewriteBase が /MOS_A/public/ 固定で
        # 8080ルートでは破綻するため、.htaccess を無効化し（AllowOverride None）
        # RewriteBase / のルーティングをここに直接書く。
        RewriteEngine On
        RewriteBase /
        RewriteRule ^$ index.php [QSA,L]
        RewriteCond %{REQUEST_FILENAME} !-f
        RewriteCond %{REQUEST_FILENAME} !-d
        RewriteRule ^ index.php [QSA,L]
    </Directory>
</VirtualHost>
```

例：XAMPPが `C:\xampp` にある場合は、2箇所とも `"C:/xampp/htdocs/MOS_A/public"` になる。

> **なぜ `.htaccess` を無効化するのか**
> MOSの `public/.htaccess` は `RewriteBase /MOS_A/public/` に固定されており、ポート80の
> `/MOS_A/public` アクセスがこれに依存している。この `.htaccess` を8080ルートに流用すると
> リライト先が狂うため、8080側は `.htaccess` を無効化し、`RewriteBase /` のルールを
> vhostに直接書く。ポート80側は従来どおり `.htaccess` を使うので無影響。

### 3. 設定を反映する（Apache再起動）

- 反映前に必ず構文チェックする：`apache/bin/httpd.exe -t` が `Syntax OK` を返すこと
- **XAMPP Control Panel** で Apache を **Stop → Start**（または Restart）する
  - XAMPPのApacheはWindowsサービスではないため、`httpd -k restart` は使えない

### 4. 動作確認

```bash
# レジ用APIが 8080 で応答する（200が返り、注文のJSON配列が返る）
curl -X POST http://localhost:8080/api/orders -H "Content-Type: application/json" -d "{\"method\":\"getOrders\"}"

# ポート80の画面が従来どおり動く（影響が無いこと）
curl -o /dev/null -w "%{http_code}\n" http://localhost/MOS_A/public/
```

そのうえで、レジ（`http://localhost/regi/public/`）から注文履歴を開き、MOSの注文が表示されれば連携成功。

## レジ側の設定

`regi/src/Config/mos.php` の `base_url` は **`http://localhost:8080` のままでよい**（変更不要）。
上記のとおりMOSを8080で配信することで、レジのデフォルト設定のまま届く。

## 契約テスト（任意）

レジ側が用意した契約テスト（`参照用/api_test_tool`）で、MOSのAPIが仕様に沿っているか確認できる。
実行にはPythonが必要（Python 3 と `pytest` / `requests`）。

```bash
python -m pip install pytest requests
cd 参照用/api_test_tool
# MOS_BASE_URL で対象を指定する（8080でも /MOS_A/public でも可）
MOS_BASE_URL=http://localhost:8080 python -m pytest -v
```

`getOrders` は注文が1件以上ある状態で実行すること（テストが「注文が存在すること」を前提にしているため）。

## うまくいかないとき

| 症状 | 原因と対処 |
| --- | --- |
| `httpd.exe -t` でパスのエラー（`AH00112` 等） | vhostの `★ここを自分のパスに★` を書き換えていない、または `\` で書いている。`/` の絶対パスに直す。 |
| Apacheが起動しない／すぐ落ちる | 手順1・2の設定ミスの可能性。まず `apache/bin/httpd.exe -t` で構文チェックし、`Syntax OK` になるまで直す。 |
| `:8080` につながらない（他は正常） | ポート8080を別アプリが使用中。`Listen 8080` を空いている別ポートに変え、レジ側 `base_url` もそのポートに合わせる。 |
| `:8080/api/orders` が404 | vhostのリライト設定（`RewriteEngine On` 以下）が抜けている。手順2のブロックをそのまま入れる。 |
| 設定したのに反映されない | Apacheの再起動忘れ。**XAMPP Control Panel** で Stop → Start する（`httpd -k restart` は不可）。 |
| レジ側で注文が出ない（APIは200） | レジ本体（`htdocs/regi/`）が未配置・未設定の可能性。regiは別システムなので各自で用意する。 |
